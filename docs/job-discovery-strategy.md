# 招聘检索：岗位线索与公司官网双通道

## 原则

Offer 情报局用于发现公司、招聘项目和更新，不是公司完整需求的证明。平台没有“机器人/VLA”关键词、行业标签不符或只有泛称“算法工程师”，均不能据此认定官网没有合适岗位。最终资格、在招状态和匹配度必须由官网核验。

## 两条队列

1. **岗位线索队列**：沿用现有增量抓取、内容指纹与相关性评分，优先检查明确具身、世界模型、部署优化的新增岗位。
2. **公司官网待核队列**：从抓取到的公司公告生成，保留未命中岗位关键词的公司。平台分数仅影响核验顺序，不是淘汰门槛。优先机器人/汽车/智能硬件公司、央国企研究所及大型科技企业，再轮转覆盖其他未核公司。

岗位排除不能扩大为整家公司排除；已投过某个官网URL也不表示整个公司池已核完。本人明确放弃公司仍遵守；已投公司保留只读新岗监测，但必须单独去重和检查志愿规则。第三方提供的链接标为线索，未验证前不称官方地址。

## 官网核验与留痕

逐公司确认官方入口，遍历当前正式校招完整池。先记录总数、分页范围和扫描时间，再比较精确ID、完整JD、专业/届别、地点、截止、历史及配额。检索覆盖：具身/VLA/VLM/世界模型、模仿学习、机器人数据与评测、模型后训练、训练推理优化、仿真、机器人系统软件；不能只按标题搜索。

输出主投、备选、排除原因及真实能力缺口。信息不足标“待核”，接口失败标“抓取失败”，与“已核无合适岗位”分开。招聘活动年份与毕业届别分开。私企/外企应用型AI、Agent开发等偏好排除在官网JD层判断，不靠平台泛化标签。

## 刷新与覆盖率

沿用 `fetch_jobs.py --list-navigations` 确认源，再以 `--full-sync` 定期覆盖全部页面，日常增量刷新。新增岗位数、源记录数、跨源去重公司数、官网已核数分别统计；平台刷新完成不等于官网核验完成。完整池已核公司按岗位更新/截止重新排队；没有新关键词的公司仍轮转复查。任何队列都不自动填写、消费志愿或最终提交。

```bash
.runtime/.venv/bin/python skills/job-hunter/scripts/fetch_jobs.py --list-navigations
.runtime/.venv/bin/python skills/job-hunter/scripts/fetch_jobs.py --phase 秋招 --full-sync
.runtime/.venv/bin/python skills/job-hunter/scripts/jobctl.py shortlist --phase 秋招 --companies --limit 30
```

`--companies` 是官网待核入口，不使用岗位 `--min-score` 淘汰公司。查看全部可用 `--limit 0 --json`；输出中的别名、网址和行业均为待核线索，不能直接生成已投记录。网址会移除查询参数，精确岗位ID必须另到官网取得。高相关队列之外，每轮保留部分核验时间给未命中关键词的公司，避免低分线索永久排在队尾。
