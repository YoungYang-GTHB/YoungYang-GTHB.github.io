# Resume Rubric

Optimize resumes by making true evidence legible for a target job. Do not fabricate or exaggerate.

## Resume Review Order

1. Read target JD and extract keywords, hard requirements, and hidden abilities.
2. Read `experience-assets.md` and `strengths.md`.
3. Map each important JD requirement to user evidence.
4. Identify missing proof before rewriting.
5. Suggest bullets using real action, method, result, and job keyword.

## Bullet Pattern

Prefer:

```text
在 <场景/项目> 中，为解决 <问题>，使用 <方法/工具> 完成 <动作>，产出 <结果/证据>，体现 <岗位关键词能力>。
```

Short resume version:

```text
使用 <工具/方法> 完成 <动作/产出>，使 <结果/指标/证据>，支撑 <岗位关键词>。
```

## Labels

Use labels in review output:

- `use_as_is`: can be used with light editing.
- `rewrite`: real evidence exists but wording is weak.
- `needs_proof`: attractive claim lacks evidence.
- `remove`: unsupported, irrelevant, risky, or fabricated.
- `ask_user`: need one more question before editing.

## Guardrails

- Do not invent numbers. If a metric is unknown, ask for evidence or use non-numeric result language.
- Do not turn team achievements into personal achievements unless the user's role is clear.
- Do not claim proficiency in tools the user only "heard of".
- Do not hide critical hard-requirement gaps.
- Keep resume and interview story bank consistent.

## Output Sections

1. JD fit diagnosis.
2. Strongest usable evidence.
3. Missing proof and questions.
4. Suggested rewrites.
5. Target resume version notes.
6. Interview follow-up risks.
