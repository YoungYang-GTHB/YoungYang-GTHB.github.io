# Offer 决策评分器

只含通用计算逻辑；个人薪酬、评价依据和评分输入必须保存在私有 `career/` 子模块。不会修改求职投递台账或执行投递。

运行：

```bash
.runtime/.venv/bin/python tools/offer-decision/evaluate.py career/求职投递/已获Offer/决策评分/2026-09-29_评分输入.json
```

## 方法

采用固定锚点、多指标加权评分和低/基准/高情景，而非把职位包装成客观的单一分数。权重初值为：税后结余 25%、技术方向 30%、稳定性 15%、城市及家庭 15%、后续机会 10%、工作环境 5%。六项权重可由本人按“从最差改善到最好，哪一项价值最大”的 swing-weighting 顺序重新分配，总和须为 100%。这是个人偏好，不是行业通用权重。

- 非财务分数 0–100：0 为明显不可接受，50 为勉强可接受，75 为较合适，100 为本人理想状态。每项必须附依据和低/基准/高范围。区间表示信息与判断的不确定性，不是统计置信区间。
- 财务分数：同一住房标准下，逐年税后可支配收入减住房、餐饮、通勤等生活成本，形成未来三年每年的低/基准/高“可自由使用结余”（万元）。三年平均结余按固定锚点线性映射至 0–100；默认年均 3 万为 0 分，20 万为 100 分。生活成本、税和兑现性未经核实时，该项保持缺失，不以税前年包替代。公积金、年金作为受限资产另记，不重复计入可花现金。
- 共同指标指数：对所有近期机会都有数据的相同维度，用相同权重归一化，供有限横向比较。已覆盖指标指数则仅在各自有数据的维度上归一化；若覆盖率不同，不能直接横比。两者都**不是完整总分**。总分可行区间：已评分项按低/高取值、缺项按 0/100 取值。区间重叠不能作稳健排序。
- `current_candidate=false` 的历史通知单独显示，不参与当前可选择机会的排序。对截止日已过、尚未确认延期的通知也必须先复核有效性。

更新口头或书面条件时，先改私库输入并写明证据，再重新运行。建议后续补齐实际税后工资、城市同品质租金、首年转正节奏、工时与签约有效性，再做权重敏感性分析。可参考英国政府 [MCDA 使用指南](https://www.gov.uk/government/publications/green-book-supplementary-guidance-use-of-multi-criteria-decision-analysis/use-of-multi-criteria-decision-analysis-in-options-appraisal-of-economic-cases) 的权重、评分和敏感性步骤，以及 [OECD 工作质量框架](https://www.oecd.org/en/publications/measuring-and-assessing-job-quality_5jrp02kjw1mr-en.html) 将收入、劳动市场安全和工作环境分别看待的思路。
